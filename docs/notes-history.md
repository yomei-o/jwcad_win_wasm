       中心 y = by - (int)((my - oy) / mmpp)      ← 切り捨て

   **潰した仮説**（どれも効きませんでした。同じ道を通らないように）:

   **答えが出ました（2026-09-25）。原典は破線の円弧を折れ線で描いています。**
   `FUN_00421490` は線種の表 `doc+0x2fc4` を引いて、そこが **-1（実線）の
   ときだけ** GDI の `Arc` を呼びます。それ以外は `FUN_0042e140` に飛び、

       p = 楕円上の点(始角);
       for (t = 刻み; |振り角| > |t|; t += 刻み) { q = 点(始角+t); 線(p,q); p = q; }
       線(p, 点(始角+振り角));          ← 最後の 1 本

   と**弦を並べます**。弦は `FUN_00436a20` →
   `FUN_004bbef0`（直線と同じ線種の描き手）に渡され、そのとき

   * **第 5 引数に 1 を渡します**（直線は 0）。これが**「線に合わせて
     伸縮する」のを止める**枝で、線種は素の大きさのまま走ります。
   * **第 4 引数がパターンの 32 ビットのレジスタで、弦をまたいで
     持ち回されます**（最上位ビットを見て、1 ビットずつ左回転）。

   つまり**刻みは弦の上で進み、角では止まりも戻りもしません**。だから
   点数でも弧長でも角度でも合わなかったのです。

   **刻み幅は「画面での大きさ」ではなく「図面のミリ」で決まります。**
   長いほうの半径 × `doc+0x1728` を階段で引きます ——
   50 未満なら 0.2、125 未満なら 0.1、312 未満なら 0.07、以下 781 で 0.04、
   1953 で 0.02、4882 で 0.01、12200 で 0.005、24400 で 0.002、
   それ以上は 0.001 ラジアン。`doc+0x1728` は画素あたりのミリの
   **分子**（`FUN_004b6d60` は `doc[6000]/doc[0x1728]` で割ります）なので
   画面では 1 です。**半径 100 mm の円弧は、どれだけ拡大しても 0.1 刻み
   （一周 63 本）**。印刷のときだけ原典が刻みを細くする
   （`4/パターン長`）のも、ミリの階段が紙の細かさを知らないからです。

   移植もそうしました（`src/draw.c` の `arc` と `line`）。**15 枚の合計が
   4,445 → 1,933 画素**、`天空率表` は 1,487 → 132、`Test1` は 193 → 28。

   ついでに分かったこと:

   * **実線の円と破線の円で環が違う**のは、片方が GDI の `Arc`、

   * 走りは**弦の端で止めます**。移植は `nbits` をパターン 2 つぶん

   **潰した仮説**（同じ道を通らないように）: 位相を ±3 ずらす（0 が最良）、

### 進む (0xe12c) が入りました —— 測り方はデコンパイルが教えてくれました（2026-10-01）

**測定装置のほうが壊れていました。**直し方はデコンパイルに書いてありました
（下の節の追記）: **戻る はまず「今の命令自身の一歩」を戻します**
（`FUN_00504100` が命令の vtable +0x40 に先に訊く。進む は +0x3c）。
だから命令が途中だと一回ぶん吸われます。線を三本引いたあと
**円へ出て線へ戻る**だけで命令側の段が空になり、そこから投げると
**一回につき一段ずつ、きれいに効きます**（`tools/probe107.sh`）:

| | 残った線 |
|---|---|
| 戻る 0 回 | 3 |
| 戻る 1 回 | 2 |
| 戻る 2 回 | 1 |
| 戻る 3 回 | 0 |
| 戻る 2 回 → 進む 1 回 | 2 |
| 戻る 2 回 → 進む 2 回 | 3 |

端のほうも訊きました（`probe108`）: **新しく一本引くと進めなくなり**ます
（戻る 2 回 → 新しい線 → 進む で何も戻りません）。**戻っていないときの
進む は何もしません**。

**そして一つ、思いがけないことが出ました。進む は戻した要素を
「前」に入れます。**線を 1・2・3 の順に引いて:

| 走り | 原典の並び |
|---|---|
| 戻る×1 → 進む×1 | **3, 1, 2** |
| 戻る×2 → 進む×1 | 2, 1 |
| 戻る×2 → 進む×2 | 3, 2, 1 |

下の二つだけなら「並びをひっくり返す」でも説明がつきますが、**一つ目が
それを否定します**（ひっくり返すなら 3,2,1 のはず）。そのために
`tools/probe109.sh` を足しました。

移植は `src/cmd.c` の `jw_cmd_redo`。戻る の段は捨てずに取っておき
（`nop` が戻れる数、`ntop` が全部の数）、新しい一歩で捨てます。要素を
足しただけの段は**前に入れ直し**、それ以外（移動や消去）は訊いていないので
**戻る直前の絵をそのまま戻します**（中身は合いますが、並びまで原典と
同じかは分かりません）。試験は `tests/redo_test.c`、答えは
`decomp/res/redo_*.jww` の十通り。

### 状態行の尻尾が出るようになりました（2026-09-30）

原典は作図中、命令の問いかけの**うしろに今描いているものの寸法**を出して
います。移植には無かったので、原典に訊いて入れました
（`tools/probe26.sh`、1/100 の紙で）:

```
線    始点を指示してください  (L)free  (R)Read   [ -26.565°]   27,380.424
矩形  始点を指示してください  (L)free  (R)Read     W=24,489.795    H=12,244.897
```

線は角と長さ、矩形は幅と高さ、円は半径。どれも**実寸・小数三桁・三桁ごと

`tests/status_test.exe` は、原典のその四行から数字を読み出して同じ組み立て
に通し、**一バイト違わず戻ること**を先に確かめてから（これで空白の数まで
決まります）、移植が描いたものについて同じことを見ます。

### 設定の 角度取得 と 長さ取得 が効くようになりました（2026-09-30）

`設定 > 角度取得` と `設定 > 長さ取得` は、傾きや寸法を**打ち込む代わりに
すでに描いてあるものから取る**もので、メニューの総ざらい
（`tests/menusweep_test.exe`）で「応えない」と出ていたものです。

**どこにも見えない値でした。**押しても命令バーの二つの箱は空のまま、
状態行も元に戻ります。そこで**同じ二本目の線を、取ってから引く場合と
取らずに引く場合の二通り**描かせて差を見ました
（`tools/probe20.sh`〜`probe23.sh`）。基準線は -26.565 度・273.804:

| | 分かったこと |
|---|---|
| 線角度 (32932) | 以後の線が -26.565 度になり、長さはクリックをその向きに落とした分 —— **傾き の箱と同じ働き** |
| 線鉛直角度 (32935) | その直角 (63.435 度) |
| X軸角度 (32933) | 読み取った二点の間の角 |
| 線長 (32939) | 向きはクリックどおりで、長さが 273.804 —— **寸法 の箱と同じ働き** |
| ２点間長 (32940) | 読み取った二点の距離 |
| 続くか | **次の線にも残ります** |
| いつ消えるか | **コマンドを出ると消えます**（線→円→線で元通り） |
| 箱と両方あったら | **打ち込んだ箱が勝ちます** |

**２点間角度 (32934) だけ入れていません。**問いかけは X軸角度 と同じ二つ
（「２点間角度 ▼基準点指示▲」→「●角度点 指示」）で、クリックも二つ
取りますが、**何を置いていくのかまだ捕まえられていません**。X軸角度 が
すでに「二点の間の角」なので、こちらが何のためにあるのかも未解明です。
分からないものは作らない、の方です。

**間隔取得 (32948)** も入りました（上の節）。線を指示してから
**読める点**を指示すると、その点から線までの垂線の長さが 複線の間隔に
なります。

**ついでに一つ直りました。**「寸法 だけ打って 傾き は空」のとき、移植は
線を**水平**にしていました。原典に訊くと**クリックした向きのまま長さだけ
その値になります**（寸法 50・1/100 で 0.5 mm、逆向きにクリックすれば逆
向き。`tools/probe23.sh`）。`tests/sized_test.c` は 傾き と 寸法 を両方
入れた場合しか見ていなかったので、ここは穴でした。
